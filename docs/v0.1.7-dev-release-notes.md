## 单模型祖先概率与节点映射

启用 ancestral_probabilities 或 split_probabilities 的保存分析结果现在包含 posteriors/。
其中 nodes.tsv、edges.tsv、areas.tsv、states.tsv 明确记录树和状态空间；
node_posteriors.tsv 与 split_posteriors.tsv 分别保存范围概率和分裂情景概率。

- 分析结果：biogeo-analysis-result-v3。
- 单模型后验：biogeo-single-model-posteriors-v1。
- 节点范围概率使用 branch-top 位置；不能把分裂三元组概率当作范围概率。
- 节点 ID 只在该次解析的树及其派生结果中稳定，不等于 R 的 ape 编号。
- 概率未请求时不输出对应表，读取方应区分未计算与概率为零。

字段、标签编码、非现生末端和直接祖先规则见 [单模型后验接口](single-model-posteriors.md)。

## 生物地理随机历史与来源

### BSM v3

full、compact 和 summary 各有单目录/分片 v3 格式。
cladogenetic_splits.tsv 保存 range_copying、subset_sympatry、vicariance、founder_event
中的实际抽中类别，founder_daughter_order 指明目标子代。节点字典增加年龄，边字典增加子节点顺序。

summary 不保存具体路径，不能用来显示逐事件网络。
原始历史中的来源列继续明确声明是否抽样来源。独立来源后处理另存结果，不回写原历史。
同 seed 与旧版共同历史字段的一致性已有冻结 exe 对照，见 [BSM v3 说明](bsm-v3-contract.md)。

### 来源抽样：v1

bsm-assign-sources 默认使用 sample 模式，要求单独指定 --seed。
它从保存拟合恢复事件所在时期的有效矩阵，按方向性权重抽取扩散或单目标 founder 的来源；
switching 的区域对由状态转换确定。

每条来源结果使用稳定事件 ID 派生独立随机流，线程数和文件分片不改变来源结果。
全零权重报告 undetermined / zero_total_weight。
多区域 founder 目标在此模式仍报告 unsupported_multi_area_founder_target，保留旧格式含义。

### 条件路线概率：v2

~~~powershell
.\biogeo-cli.exe bsm-assign-sources --analysis-result fit --bsm-result histories --allocation-mode probabilities --output-dir routes
.\biogeo-cli.exe bsm-sources-inspect --analysis-result fit --bsm-result histories --source-result routes --deep
~~~

此模式不传 --seed。对 AB -> CD，候选为 A→C、A→D、B→C、B→D，
概率由当前时期这四项有效权重归一化得到。
j、范围大小权重、区域对数量和祖先行归一化对已给定分裂中的所有区域对相同，在条件概率中抵消。

新增三种公开格式：

- biogeo-bsm-source-attribution-v2：目录结果。
- biogeo-bsm-source-attribution-run-v2：生成命令 stdout。
- biogeo-bsm-source-inspection-v2：检查命令 stdout。

sources 分片每个原事件一行；route-candidates 分片每个正概率区域对一行，
通过 sample 和 event_id 连接。每个适用事件的候选概率和为 1。
v2 的事件记录里 source_area_index、target_area_index、conditional_probability 为 NA，
具体值统一从候选表读取，包括 switching。

候选行用于累计条件事件贡献。一次分裂的四条候选仍代表一次分裂，
不能把候选行数当作事件数，也不能把它们描述成已抽中的四次迁移。
详见 [条件路线概率与 RASP5 接入](bsm-joint-route-probabilities.md)。

## 参数优化修复

### 派生参数靠近边界

j=0.99999 时，1-j 的二进制浮点值可能略小于数学上的 1e-5。
现在仅在舍入误差容差内吸附派生值到边界，真正越界继续报错。
没有降低参数下界或修改 j 来绕开检查。BAYAREALIKE+J 的 include/exclude 均有回归。

### 停止条件与起点

Nelder-Mead 同时检查似然差和模型参数距离，修复外侧收缩接受条件，
并在最后一次允许迭代后检查收敛。标准 d/e/j 模型可以使用相同配置的 j=0 拟合提供两个额外起点；
原始起点及用户指定起点保留。严格最佳有限解仍未收敛时，最多从该解继续搜索一次。

多起点数值平局时，允许选择与严格最佳 lnL 仅相差机器舍入量的收敛起点。
明显更好的未收敛解仍保留为未收敛。
最终 lnL、参数、后验和收敛标志来自同一个选中的起点。

optimization-starts.tsv 使用 biogeo-optimization-starts-v1，
保存初值、最终参数、lnL、评估/迭代数、失败评估数、边界标记与停止原因。
每个参数占一行，界面统计起点时应按 (stage,start) 去重。

### 批处理复用

DEC→DEC+J、DIVALIKE→DIVALIKE+J、BAYAREALIKE→BAYAREALIKE+J，
只有前面的无 J 结果已收敛、参数表和共同输入匹配时才复用。
+J 仍从多个起点搜索。单独运行 +J 或条件不满足时，沿用内部 j=0 拟合。

复用时不重复记 nested_j_zero 起点，也不把前一模型的评估次数算到 +J 本次评估里。
验证的小树中，include 六模型总评估数由 3445 降为 3008，
exclude 由 3238 降为 2826；两种设置的最终模型参数、lnL 与比较表一致。
这不是对任意数据墙钟加速比例的承诺。

细节见 [优化审计](optimization-audit-20260929.md)、
[平局选择](optimizer-selection-fix-20260930.md)和[无 J 拟合复用](nested-j-fit-reuse-20260930.md)。

## 四端点模型比较

四端点的无 J 模型 k=2 时 AICc 有定义；+J 的 k=3 时 n-k-1=0，AICc 不可用。
以前“有分数却没有比较权重”的合法情况在汇总转换中触发 panic，现已修复。

AIC 比较正常保留。AICc 的权重和排名只有在全部合格候选都有该准则时才生成，
不会对剩下的一部分模型暗中重新归一化。
明确要求按不可用 AICc 自动选择 BSM 模型时，返回结构化错误和退出码 2。
读取方应把 NA 显示为不可用，不能把这次分析整体判为失败。

## 升级现有 RASP5

从 0.1.3 升级：替换 exe 及同包 schemas，现有拟合、模型比较、后验、BSM v3 调用保持兼容。
新增功能需要主动调用 probabilities 模式并读取上面的三种 v2 格式。
不要把公开格式列表长度写死；按实际格式 ID 判断是否具备所需功能。

旧结果可以继续保存和检查。若要应用新的优化选择或批处理复用，在新输出目录重新运行。
--resume 会复用已完成拟合，不会重算旧的优化起点选择。
因四端点汇总崩溃留下的完整拟合可以按原请求恢复汇总。

从 0.1.0 升级：还需接入保存结果 v3、单模型 posterior v1 和 BSM v3。
不能仅凭旧历史中的状态三元组补造原来没有保存的分裂类别。
详细字段见包内 schemas 和 [RASP5 接入手册](rasp5-integration-handbook.md)。

## 验证及平台

- Rust 工作区：457 项通过，2 项既有外部输入测试默认跳过；发布前重跑。
- Clippy --all-targets -- -D warnings 通过；Windows 包构建后运行公开 CLI 示例。
- 0.1.7 四区域、两时期示例有 512 份历史、7,540 条事件、82 个多区域 founder。
- 6,030 条候选概率与 R 双精度计算的最大差为 1.1102230246251565e-16。
- 直接调用原 cladoRcpp 构造函数核对区域对贡献；它使用 float 中间值时存在已记录的舍入差。
- R 每时期另做 200,000 次条件分类抽样，频率通过事先设定的检查。
- 冻结 0.1.6 exe 对照：同 seed 的 86 个历史数据/字典/分片文件一致，metadata 仅引擎版本不同。
- 旧来源抽样的 5 个文件一致；v2 在 1/3 workers 下的 64 个文件一致。

历史数值审计没有通过给 lnL 加偏移量来对齐 R，也没有把独立优化得到的 R 解当作必然全局最优。
原始报告见 [来源分配](bsm-source-attribution-test-report.md)和[多目标概率](bsm-joint-route-test-report.md)。

已验证平台仍是 Windows x86_64 MSVC。单模型似然/优化为 1 个计算 worker，
BSM 支持多线程。Linux、Slurm 和服务器资源检测没有在本次发布中补做验证。
