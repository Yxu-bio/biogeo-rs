# 多起点拟合的收敛平局选择修复

版本：`0.1.5-dev.20260930`，Windows x86_64 MSVC，本地开发交付，未发布到 GitHub。

## 问题

RASP5 提供的脚本生成八端点、三区域测试树，包含 null range，DEC+J，
每起点最多 200 次迭代、初始步长 0.2、tolerance=1e-8、max_range_size=3。
这不是 Rosa 数据。

| 目标模型起点 | lnL | 迭代数 | 实际停止原因 | 旧版选择 | 修复版选择 |
|---|---|---|---|---|---|
| 1 | -6.88374953447813365 | 200 | iteration_limit | 是 | 否 |
| 2 | -6.88374953447813454 | 158 | converged | 否 | 否 |
| 3 | -6.88374953447813542 | 132 | converged | 否 | 否 |
| 4 | -6.88374953447813365 | 36 | converged | 否 | 是 |

旧版只在新起点的负 lnL 严格更小时替换已选结果，因此保留了未收敛的起点 1。
起点 4 的完整浮点参数与起点 1 相同，不只是显示四舍五入后相同。
原始记录中的 `optimization_converged=false` 与 `optimization_converged_starts=3`
分别描述所选起点和所有起点，但在这个例子中选择策略不合理。

## 修复规则

1. 先找所有有限结果中严格最高的 lnL，以此作为固定基准。
2. 基准起点已收敛时保留它；否则，在与基准数值平局的收敛起点中选择 lnL 最高的一个。
3. 平局阈值为 `min(tolerance, 8 * f64::EPSILON * max(1, abs(最佳 lnL)))`。
   在本例约为 `1.22e-14`，远小于优化停止容差 `1e-8`。
4. 相同 lnL 且相同收敛状态时保留靠前起点。阈值始终相对严格基准计算，不会连续放宽。
5. 没有等价收敛解时，保留真正更好的未收敛解，仍报告未收敛。

仅改变多个运行结果之间的最终选择，不改变 Nelder-Mead 的迭代、收敛判断、
初始点策略、严格最优起点上的一次重启或迭代预算，不修改似然、参数边界和后验算法。
最终参数、lnL、后验和收敛标志均来自同一个被选中的起点。
不会把其他起点的收敛标志嫁接到未收敛起点，也不会把任意收敛的较差局部解拿来充数。
优化器报告收敛不代表已证明全局最优。

## RASP5 使用方式

公开 schema 不变，仍使用 `biogeo-optimization-starts-v1` 和原分析结果/模型比较格式。
RASP5 无需改结果解析逻辑，替换开发版引擎后在新输出目录重新运行原请求即可：

```powershell
.\biogeo-cli.exe model-workflow --request <原workflow.tsv> --output-dir <新目录>
```

**不要只在旧目录执行 `--resume`，期望它自动修正已经保存的拟合。**
resume 按原契约复用已完成结果，不会重新优化或重新判定旧的所选起点。
本次未编写结果迁移或静默改写旧诊断的逻辑。

交付目录包含 exe、engine-info、全部 schema、教程、此报告及测试证据；
`biogeo-cli.exe.sha256`、`SHA256SUMS.tsv` 和压缩包旁的 `.sha256` 用于核对文件。
